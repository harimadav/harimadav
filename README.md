## <img src="https://media.giphy.com/media/iY8CRBdQXODJSCERIr/giphy.gif" width="32"/> About Me

<img align="right" width="260" src="https://user-images.githubusercontent.com/74038190/212257468-1e9a91f1-b626-4baa-b15d-5c385fb01e5b.gif">

I like software that does exactly what it says it does — nothing more, nothing less.

Most of my work lives in that space between *learning a concept* and *shipping something that actually runs*: a Flask API that stores real data instead of mock JSON, a WebSocket app where two browser tabs genuinely talk to each other in real time, a weather app I didn't build from scratch but rebuilt the parts that mattered.

My approach to learning has stayed fairly consistent —

> 🔹 Pick something slightly outside my comfort zone
> 🔹 Build the smallest working version of it
> 🔹 Go back and make it *correct* — cleaner structure, better error handling, code a stranger could read without asking questions

I care more about a project working end-to-end than about it looking impressive on paper. If a technology shows up in one of my projects, it's because the project actually needed it — not because it looks good in a README.

Right now that means backend fundamentals, real-time communication, and getting comfortable enough with the frontend that I don't need to hand it off. Long-term, I'm heading toward full-stack and AI-adjacent engineering — the Text & Speech Analytics coursework I'm working through (Word2Vec, CBOW, Skip-Gram) is the start of that shift.
