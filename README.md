## <img src="https://media.giphy.com/media/WUlplcMpOCEmTGBtBW/giphy.gif" width="28"> About Me

I like software that does exactly what it says it does — nothing more, nothing less. Most of my work so far lives in that space between "learning a concept" and "shipping something that actually runs": a Flask API that stores real data instead of mock JSON, a WebSocket app where two browser tabs genuinely talk to each other in real time, a weather app I didn't build from scratch but rebuilt the parts that mattered.

I'm a Computer Science Engineering student, and my approach to learning has been fairly consistent: pick something slightly outside my comfort zone, build the smallest working version of it, then go back and make it correct — better error handling, cleaner structure, code that a stranger could read without asking me questions. I care more about a project working end-to-end than about it looking impressive on paper.

Right now that means backend fundamentals (REST APIs, CRUD, data flow), real-time communication with WebSockets, and getting comfortable enough with the frontend to not need to hand it off to someone else. Long-term, I'm heading toward full-stack and AI-adjacent engineering — the Text & Speech Analytics coursework I'm currently working through (Word2Vec, CBOW, Skip-Gram) is part of that shift.

I don't chase trends for the sake of a resume line. If I add a technology to a project, it's because the project needed it.

### 📚 RESTful API Development
**A Flask-based library management API**

Built a CRUD API from scratch — no frontend, pure backend logic — to manage a book inventory (id, title, author, year). Every endpoint was tested manually and systematically with Postman before being called "done."

**Solved:** demonstrating that data can be reliably created, read, updated, and deleted through clean HTTP endpoints, without a database engine to lean on.

**Stack:** `Python` `Flask` `JSON storage` `Postman`

**Engineering decision:** kept persistence in a flat JSON file on purpose — it forced explicit handling of read/write consistency instead of outsourcing that problem to an ORM.

**What I learned:** how much of "backend development" is really about designing predictable request/response contracts.

[🔗 View Repository](https://github.com/harimadav/RESTFUL-API-DEVELOPMENT)

### ⚡ Real-Time Collaboration Tool
**A Google Docs–style live shared editor**

A browser-based text editor where every keystroke from one client is broadcast instantly to every other connected client — built with Flask on the backend and Socket.IO handling the WebSocket layer.

**Solved:** synchronizing shared state across multiple open sessions in real time, without page reloads or polling.

**Stack:** `HTML` `CSS` `JavaScript` `Flask` `Socket.IO`

**Engineering decision:** used WebSocket events instead of REST polling — the right tool for a problem that's fundamentally about push, not pull.

**What I learned:** multi-client state synchronization, and how quickly "simple" real-time features get complicated once more than one user is involved.

[🔗 View Repository](https://github.com/harimadav/REAL-TIME-COLLABORATION-TOOL)

## 🧠 Engineering Philosophy

I'd rather ship something small that works correctly than something large that mostly works. Every project above started as the minimum viable version and got refined afterward — that order matters to me.

A few things I try to hold myself to:

- **Read before you write.** The refactoring project taught me this directly — understanding *why* code is structured a certain way before changing it saves more time than it costs.
- **Constraints are useful, not annoying.** Scoping a change to two files, or a data layer to a single JSON store, forces cleaner thinking than having infinite freedom does.
- **Test the way a user would.** Manually verifying every CRUD endpoint in Postman before calling an API "done" isn't optional — it's the actual definition of done.
- **Stay curious past the assignment.** Coursework is a starting point, not a ceiling — the NLP work I'm doing now started as a class requirement and turned into genuine interest.
